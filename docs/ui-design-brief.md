# minbox UI デザイン要件

minbox の画面デザインを任せるための資料です。

いまある機能はひととおり動いています。この作業の目的は次の 3 つです。

1. **見た目と使い勝手を良くする**
2. **スマホで使えるようにする**
3. **アーカイブと検索を足す**

サーバーと mod は、原則として変えません。ただし、アーカイブと検索に必要な API とストアの変更だけは行ってかまいません(§3.6、§3.7)。

## 1. minbox とは

- **何をするアプリか:** Claude Code のセッションを PTY で動かし、それぞれのセッションのターミナルと Inbox(Claude との非同期のやり取り)を 1 画面に並べる Web アプリです。
- **誰が使うか:** 複数の Claude Code セッションを並行して走らせる開発者 1 人です。
  - デスクトップでは、ターミナルと Inbox を並べて作業します。
  - スマホでは、主に離れた場所から状態を確かめ、質問に答えます。ターミナルでの短い操作にも使います。
- **このアプリの価値:** どのセッションが自分を待っているかがすぐわかり、ターミナルを切り替えずに質問へ答えられることです。
- 詳しくは `WHAT.md` と `README.md` を見てください。移植元の表示は `THIRD_PARTY_NOTICES.md` にあります。

## 2. 変えてはいけないこと(制約)

- **技術:** React 19 + Vite + Tailwind CSS v4(`web/`)を使います。
  - ターミナルの描画は **ghostty-web** です。**xterm.js は禁止**です。
  - UI ライブラリを足すのはかまいませんが、軽いものにしてください。ビルド結果は Go バイナリに埋め込まれます。
  - 外部 CDN やフォントは読み込まないでください。オフラインで動く必要があります。
- **デスクトップは 3 カラム構成:** 幅が広い画面では、セッション一覧 / ターミナル / Inbox の 3 カラムを保ってください。狭い画面での構成は §3.5 に書いています。
- **テストの手がかり:** `data-testid` とその他の `data-*` 属性、ARIA role を残してください。e2e テスト(`web/e2e/*.spec.ts`)がこれらに依存しています。対象は次のとおりです。
  - `data-testid`
    - セッション一覧: `session-list` `session-row` `session-menu` `menu-stop` `menu-restart` `new-session` `new-session-cwd` `new-session-name` `new-session-start` `badge-questions` `badge-unread`
    - ターミナルまわり: `terminal` `resume` `notice`
    - Inbox の一覧と新規作成: `inbox-pane` `compose` `compose-subject` `compose-body` `compose-send` `thread-list` `thread-row` `delivery-tick`
    - スレッド表示: `thread-view` `thread-back` `thread-subject` `message` `delivery-line`
    - 質問と返信: `question-card` `question-state` `choice` `choice-other` `question-text` `accept-recommended` `skip-question` `answer-summary` `reply-box` `reply-send`
  - その他の `data-*` 属性: `data-session-id` `data-thread-id` `data-question-key` `data-author` `data-delivery`
  - ARIA role: 選択肢は `role="radio"`(単一選択)/ `role="checkbox"`(複数選択)と `aria-checked` を持ちます。
  - テストが文言を見ている箇所:
    - セッションの状態ラベル: `Waiting for you` / `Working` / `Ended`
    - 質問の状態: `Answered` / `Skipped`
    - Inbox が空のとき: `No messages yet`
    - その他: `Recommended`、`N of M answered`、セクション名の `Waiting on you`
    - 文言を変えるときは、テストも合わせて直してください。
  - 新しく作る要素にも `data-testid` を付けてください。名前の案は §3.5〜§3.7 にあります。
- **キー操作(デスクトップ)は変えないでください:**
  - `J` / `K`: スレッドの移動
  - `R`: 返信欄に移る
  - `Esc`: 一覧に戻る
  - `⌘↵`: 送信
  - ターミナル内の `⌘V`: 画像の貼り付け
  - ターミナルにフォーカスがあるときは、ターミナル以外のショートカットを発火させないでください。
  - 新しいキーは、`E`(アーカイブ)と `/`(検索)を足します。
- **振る舞い:**
  - 選択状態は URL の hash(`#s=<session>&t=<thread>`)に持ちます。
  - データの更新は SSE で届きます。

## 3. 画面と要素

すべての要素について、空の状態、読み込み中、エラーのときの見た目も決めてください。

### 3.1 セッション一覧(左カラム。いまは幅 240px 固定)

- **ヘッダー:** ロゴ(`public/favicon.svg`)、「minbox」、`+ New` ボタン。
- **新規作成フォーム:** ディレクトリ(既定は前回の値)、名前(省略可)、「Start Claude Code」ボタン。セッションが 0 件のときは最初から開いておきます。
- **セッション行:**
  - 1 行目: 状態ドット、名前、`?N`(答えていない質問の数)、未読数。
  - 2 行目: cwd(`~` からの相対パス)と状態ラベル。
  - 状態は 4 つです。

    | 状態 | ラベル | 意味 |
    | --- | --- | --- |
    | starting | Starting | 起動中 |
    | working | Working | Claude がターンを実行中 |
    | idle | Waiting for you | 入力待ち |
    | ended | Ended | 終了 |

  - **「人を待っている」セッションを最も目立たせてください。** 対象は、答えていない質問があるか、未読があるセッションです。
- **行メニュー:** ホバーで出る `⋯` か右クリックで開きます。項目は Rename、Stop または Resume、Archive(§3.6)、Delete です。
  - いま Rename と Delete はブラウザ標準の `prompt()` / `confirm()` を使っています。**アプリ内のダイアログかインライン編集に置き換えてほしい**です。

### 3.2 ターミナル(中央カラム。残りの幅をすべて使う)

- ghostty-web のキャンバスです。中身の配色はターミナル側で決まります。デザインするのは**ターミナルの外枠**(余白、背景、周りとのつながり)です。
- **終了したセッション:** 下部に「Session ended (exit N).」と `Resume` ボタンのバーを出します。
- **セッションが 1 つもないとき:** 空の状態を表示します。いまは「Start a session to run Claude Code.」と出しているだけです。
- **通知(`notice`):** 画面下中央のトーストです。通常は 3 秒、エラーは 6 秒で消えます。例: 「Pasted image: …」、エラーメッセージ。
- **追加してよい要素:** セッション名、cwd、状態を示すヘッダー。

### 3.3 Inbox(右カラム。いまは幅 400px 固定)

**スレッド一覧**

- **ヘッダー:** 「Inbox」、検索(§3.7)、`✎ New message` ボタン。
- **新規メッセージフォーム(Compose):** 件名と本文を入力して送信します。
- **セクション:** 次の順に並べます。
  1. `Waiting on you`: Claude の質問や依頼が返事を待っている
  2. `New`: 未読
  3. `Sent · waiting on Claude`: 人の返信を Claude が処理中
  4. `Quiet`: 落ち着いたスレッド
  5. `Archived`(§3.6): 既定では畳んでおく
- **スレッド行:** 件名、最後のメッセージの 1 行抜粋、時刻、`?N`、未読の印、配信状態。
  - 配信状態は 4 つです。

    | 状態 | 表示 | 意味 |
    | --- | --- | --- |
    | queued | ◷ | 送信待ち |
    | sending | … | 送信中 |
    | delivered | ✓✓ | 配信済み |
    | undelivered | △ | 未配信。セッションが止まっている |

- **空の状態:** 「No messages yet. Claude writes here when it needs you or finishes work.」

**スレッド表示**

- **ヘッダー:** ← 戻る、件名、`Mark unread`、`Archive` / `Unarchive`。
- **メッセージ:**
  - Claude のメッセージ: 本文は Markdown(見出し、リスト、コード、表、引用)です。本文の途中に**質問カード**が埋め込まれます。
  - 人のメッセージ: 本文と、送った回答の要約です。
  - 最後の人のメッセージの下に、配信状態の行(`delivery-line`)を出します。
- **返信欄:**
  - テキストエリアと Send ボタン(`⌘↵`)。
  - 上部に「N of M answered · K stay open」を出します。
  - 下書きは自動で保存され、「Draft saved」と表示します。
  - セッションが終了しているときは、プレースホルダーで「再開すると届く」ことを伝えます。

**質問カード(デザインの中心です)**

- **ヘッダー:** `Q1 · pick one / pick any / free text` と、状態(`Open` / `Draft` / `Answered` / `Skipped` / `Closed`)。
- **本文:** 質問文と、補足の Markdown(省略可)。
- **選択肢:** ラベルと説明を出します。印は `Recommended`(Claude の推奨)と `decided`(決定済み)の 2 種類です。単一選択はラジオ、複数選択はチェックです。
- **「Other…」:** 自由入力欄です。自由記述の質問はテキストエリアにし、`Suggested: …` をプレースホルダーに出します。
- **操作:** `Add note`(Claude への一言)、`Accept recommended`、`Skip` / `Unskip`。
- **回答できなくなった状態:** 次のカードは読み取り専用で表示します。
  - 回答済みのカード(`Answered` / `Skipped`)
  - 新しいメッセージが来て閉じたカード(`Closed`)
  - アーカイブで閉じたカード(`Closed`)

### 3.4 画面全体

- **タブタイトル:** `(N) minbox` です。N は待っている件数です。
- **通知:** タブが裏にあるときにセッションが待ち状態になると、ブラウザ通知を出します。
- **テーマ:** いまはダークテーマだけで、色は zinc 系とアクセントの amber です。ライトテーマ(`prefers-color-scheme` に従う)を足すかどうかは任せます。

### 3.5 スマホ・狭い画面

**レイアウト**

- **幅 768px 未満(スマホ):** 1 カラムで、画面を順にたどる形にします。
  - 画面のたどり方は「セッション一覧 → セッション画面 → スレッド表示」です。
  - セッション画面では、`Inbox` と `Terminal` をタブで切り替えます。既定は `Inbox` です。スマホでは質問に答えるのが主な用途だからです。
  - ブラウザの「戻る」で、一つ前の画面に戻れるようにしてください。スマホでは hash の変更を履歴に積みます(いまは `replaceState`)。
  - 待っているセッションがあることを、どの画面にいてもわかるようにしてください。例: ヘッダーのバッジ。
- **幅 768〜1279px(タブレット・狭いウィンドウ):** 構成は任せます。例: セッション一覧を引き出し式にして、ターミナルと Inbox の 2 カラムにする。
- **幅 1280px 以上:** これまでどおり 3 カラムです。

**タッチ操作**

- タップできる領域は 44px 以上にしてください。
- ホバーや右クリックに頼る操作は、スマホでは常に見えるボタンかスワイプに置き換えてください。対象は行メニューの `⋯` です。
- スレッド行の左右スワイプでアーカイブできると良いです(任意)。

**スマホのターミナル**

- **補助キーの列:** ソフトウェアキーボードの上に、次のキーを並べてください。
  - `Esc` `Tab` `Ctrl`(次のキーと組み合わせる)`↑` `↓` `←` `→` `⏎`
  - `Ctrl-C`
  - 画像のアップロード: ファイル選択またはカメラ。`⌘V` の代わりで、既存の `/uploads` を使い、パスをターミナルに入力します。
- **PTY のサイズを変えない:** スマホで開いたときは、既定で PTY のサイズを変えないでください。
  - PTY は 1 つで、デスクトップと共有しています。スマホの幅に合わせて小さくすると、デスクトップ側の表示も崩れます。
  - スマホでは、いまの PTY サイズのまま縮小表示か横スクロールで見せます。「この画面に合わせる」は明示的な操作にしてください。
  - いまの実装では `web/src/Terminal.tsx` が接続時に resize を送ります。

**スマホで気をつけること**

- **キーボードの表示:** ソフトウェアキーボードが出ても、返信欄と送信ボタンが隠れないようにしてください。`visualViewport` や `dvh` を使います。
- **ノッチ:** ノッチのある端末に対応してください(`env(safe-area-inset-*)`)。

**data-testid の案:** `mobile-tab-inbox` `mobile-tab-terminal` `mobile-back` `term-key-esc` など(`term-key-*`)、`term-upload`

### 3.6 アーカイブ

**スレッドのアーカイブ**

この意味は Plannotator Inbox に合わせています。

- **アーカイブしたとき:**
  - 一覧の通常のセクションから外れ、`Archived` セクションに移ります。
  - そのスレッドで答えていない質問は `Closed` になります。
  - 未読と待ちの件数には数えません。
- **元に戻るとき:**
  - **Claude がアーカイブ済みのスレッドに新しいメッセージを書くと、自動でアーカイブが外れます**("came back")。
  - 人がアーカイブ済みのスレッドに返信しても外れます。
- **アーカイブ前に送った返信:** アーカイブ前に送った未配信の返信は、取り消さずにそのまま届けます。
- **操作:**
  - スレッド表示のヘッダーのボタン
  - キーの `E`
  - スマホではスワイプ(任意)
  - アーカイブした直後に、トーストで `Undo` を出してください。

**セッションのアーカイブ**

- 対象は**終了したセッションだけ**です。
- アーカイブすると、一覧の下の、畳んだ `Archived` に移ります。
- Resume すると、自動でアーカイブが外れます。

**API の案(Go のテストを付けて実装してください)**

| メソッドとパス | 内容 |
| --- | --- |
| `POST /api/threads/{id}/archive` / `POST /api/threads/{id}/unarchive` | スレッドのアーカイブと解除 |
| `POST /api/sessions/{id}/archive` / `POST /api/sessions/{id}/unarchive` | セッションのアーカイブと解除。終了していないセッションは `409` |

- Thread と Session の JSON に `archived_at`(`string | null`)を足します。
- Thread の `section` に `archived` を足します。
- 件数と導出の規則は `internal/store` にまとめます。対象は、Session の `unread` / `open_questions` / `waiting` と、質問の状態です。
- SSE で `sessions` / `threads` のイベントを出します。

**data-testid の案:** `thread-archive` `thread-unarchive` `archived-section` `menu-archive` `menu-unarchive` `undo`

### 3.7 検索

- **検索の対象:** スレッドの件名とメッセージ本文です。
  - 範囲の既定は、いま選んでいるセッションです。「全セッション」に切り替えられるようにしてください。
  - アーカイブ済みも含めます。結果には、アーカイブ済みであることを示す印を出します。
- **入口:**
  - Inbox ヘッダーの検索欄
  - キーの `/`
  - スマホでは、ヘッダーの検索アイコン
- **結果の表示:**
  - 各結果に、件名、セッション名(全セッション検索のとき)、一致箇所を強調した抜粋、時刻を出します。
  - 結果を選ぶと、そのセッションとスレッドを開きます。
  - 結果が 0 件のときの表示も決めてください。
- **一致の規則:**
  - 大文字と小文字を区別しません。
  - 空白で区切った語は、すべてを含むもの(AND)を探します。
  - 日本語が引けることが必須です。SQLite の FTS5 の既定のトークナイザは日本語に向かないので、まずは `LIKE` で十分です。件数が増えたら FTS5 の `trigram` を検討してください。

**API の案**

`GET /api/search?q=<words>&session_id=<id 省略可>` は、次の要素の配列を返します(新しい順、最大 50 件)。

| フィールド | 内容 |
| --- | --- |
| `thread_id`、`session_id`、`session_name`、`subject` | どのスレッドか |
| `message_id` | 一致したメッセージ(件名だけが一致したときは null) |
| `snippet` | 一致箇所の抜粋 |
| `archived` | アーカイブ済みか |
| `created_at` | 時刻 |

**data-testid の案:** `search-input` `search-scope` `search-result`

## 4. いまの課題(直してほしい点)

1. **待っているものがわかりにくい:** 「人を待っている」状態が、セッション一覧でも Inbox でも十分に目立ちません。
2. **カラム幅を変えられない:** 3 カラムの幅が固定です。カラム間をドラッグで調整できるようにし、その幅を保存してほしいです。Inbox を畳めるとなお良いです。
3. **画面が狭いとき:** 1280px 程度の幅で、ターミナルが十分な幅を保つようにしてください。
4. **ブラウザ標準のダイアログを使っている:** Rename と Delete で `prompt()` / `confirm()` を使っています。
5. **見た目が整っていない:** 余白、文字サイズ、階層がその場しのぎです。Tailwind のテーマ(`web/src/index.css` の `@theme`)にデザイントークン(色、角丸、文字サイズ)をまとめてください。
6. **フォーカスが見えにくい:** フォーカス表示とキーボード操作が見えにくいです。コントラストは WCAG AA を目安にしてください。
7. **スマホで使えない:** スマホでは画面が崩れます(§3.5)。
8. **アーカイブと検索がない:** スレッドとセッションが増える一方で、整理も検索もできません(§3.6、§3.7)。

## 5. 作業の進め方と確認方法

```sh
cd web && npm install
make build                       # リポジトリ直下で実行。bin/minbox ができる
make test-go                     # サーバーやストアを変えたとき
cd web && npm run typecheck
cd web && npx playwright test    # 全件通過を保つ(偽の claude を使うのでモデル呼び出しなし)
cd web && SCREENSHOTS=1 npx playwright test screenshot   # 主な状態のスクリーンショットを出力する
```

- **画面を見ながら開発するとき:** リポジトリ直下で `./bin/minbox --data-dir /tmp/mbx-dev --claude "python3 $PWD/web/e2e/fake-claude.py"` を実行して起動すると、偽の claude で画面を確かめられます。偽の claude のパスは絶対パスにする必要があります。
  - 偽の claude のターミナルでは、次の入力で状態を作れます。

    | 入力 | 起きること |
    | --- | --- |
    | `ask` | 質問付きのスレッドができる |
    | `say <text>` | Claude からのメッセージが届く |
    | `exit` | セッションが終了する |

  - フロントだけを変えるときは、上のサーバーを 4848 番で起動して `cd web && npm run dev` を実行します。
- **スマホの確認:** Playwright のデバイスエミュレーション(例: `devices['iPhone 15']`、`devices['Pixel 7']`)で行います。
  - `web/playwright.config.ts` に mobile 用の project を足してください。
  - サーバーはループバックでしか待ち受けないので、実機ではつながりません(§7)。
- **足してほしい e2e テスト:**
  - スマホ幅で、セッションを選び、質問に答え、配信されるまで
  - スマホのタブ切り替えと、戻る操作
  - スマホで開いても PTY のサイズが変わらないこと
  - スレッドのアーカイブ、Undo、Claude の書き込みで自動的にアーカイブが外れること
  - 終了したセッションのアーカイブと、Resume でアーカイブが外れること
  - 検索: 日本語の語と、全セッションを対象にした検索
- **スクリーンショットで確かめてほしい状態:**
  - セッション 0 件、質問が開いたまま、回答済み、未配信、終了したセッション、アーカイブ、検索結果
  - 幅は 390px(スマホ)、1024px、1280px、1500px

- アーカイブと検索に必要なサーバーとストアの変更、および Go のテスト。
- e2e テストが全件通過したままであること。文言を変えた箇所はテストも更新してください。§5 のテストも足してください。
- 変更前後のスクリーンショットと、決めたデザイン方針の短いメモ(色、文字、余白、状態の表し方、スマホでの画面のたどり方)。

## 7. 対象外

- アーカイブと検索以外の、サーバー API、データモデル、mod の変更。UI に新しいデータが必要になったら、変更せずに提案としてまとめてください。
- ターミナルの中身の描画方法の変更(ghostty-web はそのまま使います)。
- スマホの実機からつなぐ経路。ループバック以外で待ち受けることや、その認証は、別に決めます。
- スマホへのプッシュ通知(PWA の Web Push)。
